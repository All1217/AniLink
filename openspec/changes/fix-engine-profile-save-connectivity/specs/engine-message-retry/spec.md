# Spec Delta

## Purpose

让画像消息在消费失败时有界重试并进入死信队列，避免同一条消息被无限重投造成持续刷屏，同时保证确认动作在正确的线程执行。

## ADDED Requirements

### Requirement: 有界重试
画像消息消费失败时 MUST 最多重试有限次数（默认 3 次，可配置）；超过上限后 MUST 停止重投。

#### Scenario: 重试后成功
- **WHEN** 前两次消费因临时数据库错误失败，第三次成功
- **THEN** 消息被确认，不再重投

#### Scenario: 超过重试上限
- **WHEN** 同一消息连续失败达到上限
- **THEN** 消息不再回到原队列，改为进入死信队列

### Requirement: 死信可追踪
超过重试上限的消息 MUST 投递到固定的死信队列，并保留原始消息体与失败原因，便于人工排查。

#### Scenario: 查看失败消息
- **WHEN** 运维查看死信队列
- **THEN** 能看到原始 uid、消息体与最后一次失败原因

### Requirement: 确认线程约束
ack、nack 与重投 MUST 在消费者线程或通过连接线程安全回调执行，工作线程 MUST NOT 直接操作 pika channel。

#### Scenario: 工作线程完成处理
- **WHEN** 线程池中的任务成功或失败
- **THEN** 确认动作通过线程安全回调回到消费者线程执行

### Requirement: 重投幂等
同一条画像消息被重复投递时 MUST 不产生重复标签或重复错误；处理结果与只投递一次一致。

#### Scenario: 消息重复投递
- **WHEN** 同一条 uid 消息被投递两次
- **THEN** 两次画像保存都成功且最终标签一致，不抛唯一键冲突
