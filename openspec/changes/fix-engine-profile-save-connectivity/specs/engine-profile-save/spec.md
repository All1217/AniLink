# Spec Delta

## Purpose

保证用户画像标签在重复或并发构建时幂等写入，不因唯一键冲突失败，也不会出现旧标签已删除、新标签未写入的空画像。

## ADDED Requirements

### Requirement: 标签写入幂等
同一用户同一标签的重复写入 MUST 更新已有记录的权重，而不是抛出唯一键冲突；最终每个 `(uid, tag_name)` 只有一条记录。

#### Scenario: 同一用户重复构建
- **WHEN** 同一用户连续两次完成画像构建并保存标签
- **THEN** 每个标签只保留一条记录，权重为最后一次构建的值

#### Scenario: 并发构建同一用户
- **WHEN** 同一用户的两个画像构建同时保存标签
- **THEN** 两次保存都成功，不出现 `Duplicate entry`，数据库只保留一套标签

### Requirement: 同一用户串行写库
同一用户的标签保存 MUST 串行执行；一个构建的删除与写入不得与另一个构建交错。

#### Scenario: HTTP 与 MQ 同时触发
- **WHEN** `/userProfile/<uid>` 与 MQ 消息同时为同一用户构建画像
- **THEN** 两次写库按顺序完成，最终标签集合等于最后一次构建的结果

### Requirement: 失败原子性
标签保存失败时 MUST 保留该用户原有标签，不得因为先删除旧标签而留下空画像。

#### Scenario: 写入阶段数据库报错
- **WHEN** 删除旧标签后、写入新标签时数据库报错
- **THEN** 该用户仍保留删除前的标签，错误被记录并可重试

### Requirement: 旧标签清理
新标签集合写入后，系统 MUST 删除该用户不在新集合中的旧标签；新集合为空时 MUST 清空该用户全部标签。

#### Scenario: 标签数量减少
- **WHEN** 本次构建只产出标签 A，而数据库里原有 A、B
- **THEN** 保存后只保留 A，B 被删除

#### Scenario: 空标签集合
- **WHEN** 本次构建没有产出任何标签
- **THEN** 该用户原有标签被清空，不保留过期标签
