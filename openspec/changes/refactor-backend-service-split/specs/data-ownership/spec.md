# Spec Delta

## Purpose

建立“一表一主”的数据归属与跨域访问规则，保证拆分后的服务不越权读写他域数据，并为后续数据库 schema 隔离留出可执行的演进路径。

## ADDED Requirements

### Requirement: 表单一属主
每张持久化表 SHALL 有且只有一个属主服务拥有写权限；非属主服务 MUST NOT 直接写该表，包括批量更新、删除与 upsert。

#### Scenario: 写入路径盘点
- **WHEN** 搜索任一表的写入方
- **THEN** 只有属主服务的 Mapper 或仓储代码出现写操作，其他服务只通过接口或事件间接影响数据

#### Scenario: 计数器回写
- **WHEN** 收藏或点赞发生变化
- **THEN** 属主服务根据事件更新计数表，其他服务不直接执行计数 UPDATE

### Requirement: 禁止跨服务 SQL
服务 MUST NOT 在 SQL、JOIN 或子查询中引用非属主表；跨域读取 MUST 通过内部批量接口或事件投影完成。

#### Scenario: 评论列表作者信息
- **WHEN** 评论分页需要展示作者昵称与头像
- **THEN** 评论服务批量调用用户服务的内部接口获取资料，不 JOIN 用户表

#### Scenario: 视频列表作者信息
- **WHEN** 视频分页需要展示 UP 主信息
- **THEN** 视频服务通过用户服务批量接口补全，不 JOIN 用户表

### Requirement: 跨域计数最终一致
收藏、点赞等跨域计数 SHALL 通过幂等事件更新，允许秒级延迟；MUST NOT 采用跨服务同步双写。

#### Scenario: 收藏状态变化
- **WHEN** 用户收藏或取消收藏视频
- **THEN** 收藏服务发布状态变化事件，视频服务幂等消费并更新用户×视频交互计数与视频统计

#### Scenario: 事件重复投递
- **WHEN** 同一事件被重复消费
- **THEN** 计数结果与只消费一次相同

### Requirement: 共享库阶段的归属约束
数据库 schema 尚未拆分时，表归属 MUST 作为逻辑约束生效；服务 MUST NOT 依赖同库中非属主表的存在或结构。

#### Scenario: 同库不同域
- **WHEN** 视频服务连接共享库执行查询
- **THEN** 其 SQL 只引用视频域表，用户、社交、评论等表不可见也不可用

### Requirement: 拆分就绪性
表归属、跨域接口与事件契约 MUST 在文档中维护，并能通过静态检查发现越界引用，使后续按服务拆 schema 不需要修改接口契约。

#### Scenario: 静态检查越界
- **WHEN** 代码中出现对非属主 Mapper 或表名的引用
- **THEN** 架构检查失败并指出具体类与方法
