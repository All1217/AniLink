## 1 认识虚拟环境

虚拟环境介绍：[6-保存和复制虚拟环境_哔哩哔哩_bilibili](https://www.bilibili.com/video/BV1V7411n7CM?spm_id_from=333.788.videopod.episodes&vd_source=eeeee0aca2e1dbd0def2d87b9c6d7397&p=6)

视频没有详细介绍conda环境，anaconda提供的虚拟环境和python3自带的venv不一样，你通过anaconda创建过的一系列虚拟环境通常存放在：C:\用户\你的用户名\anaconda3\envs。

一般不要随意切换虚拟环境，要么用python自带的，要么用其他产品（比如anaconda），而且还要注意有时候Pycharm会莫名奇妙帮你切换虚拟环境。

### 1.1 如何判断当前虚拟环境？

1. **查看 PyCharm 右下角**：会显示当前使用的解释器，例如：
   - `Python 3.9 (venv)`
   - `Python 3.11 (mycondaenv)`
   - `Python 3.8 (系统解释器)`
2. **查看 PyCharm 终端**：命令行提示符前面会有环境名称，例如：
   - `(venv) C:\project>`
   - `(mycondaenv) C:\project>`
3. **PyCharm 设置中查看**：
   - `File` → `Settings` → `Project` → `Python Interpreter`
   - 这里会明确显示当前使用的是哪个解释器

### 1.2 激活虚拟环境

在pycharm根据提示框引导选择虚拟环境，在创建项目时也可以改。或者打开命令行输入`python -m venv [项目名]`，会直接复制依赖并在本地创建目录。

## 2 如何复制环境？

主要是记录这个项目所处虚拟环境装过什么包。

### 2.1 法一

激活虚拟环境后，在根目录打开终端输入：`pip freeze > requirements.txt`。此时根目录出现名为`requirements.txt`的文件，该法会把所有相关或不相干的包记录进去

### 2.2 法二

安装`pip install pipreqs`，再在根目录运行`pipreqs . --force`，`--force` 会覆盖根目录已存在的 `requirements.txt`，也可以指定输出目录：`pipreqs src --force --savepath "$env:USERPROFILE\Desktop\requirements.txt"`（输出到桌面）

# [2026/11/25] 画像构建 user_tag 唯一键冲突与 MQ 重试

## 现象

`logs/python-log.txt` 中 Flask、MySQL、Redis、RabbitMQ 都已启动成功，但画像构建持续报：

```text
pymysql.err.IntegrityError: (1062, "Duplicate entry '<uid>-潜水观望者' for key 'user_tag.uk_uid_tag'")
```

这不是中间件断连，引擎本身已经启动。

## 根因

1. `profileBuilder.saveToDB` 先 `DELETE FROM user_tag WHERE uid=%s`，再 `executemany` 插入；连接池 `autocommit=True`，同一 uid 的并发构建会交错，第二个插入撞唯一键。
2. `buildOneProfile` 捕获了保存异常并只把 `success` 置为 False，没有继续抛出，MQ 消费者因此感知不到失败，重试/死信逻辑不会触发。
3. `rabbitmq.py` 原实现失败时 `basic_nack(requeue=True)`，若异常继续向上抛会无限重投；工作线程还直接操作 pika channel。

## 修复

- `saveToDB`：64 个条带锁按 uid 串行；显式事务；`INSERT ... ON DUPLICATE KEY UPDATE` 后清理不在新集合里的旧标签；空集合清空旧标签。
- `buildOneProfile`：预加载/保存失败向上抛出，HTTP 调用方已有 try/except，MQ 消费者可走重试。
- `rabbitmq.py`：新队列 `userProfile.queue.v2`（带 DLX 参数）、死信交换机 `userProfile.dlx`、死信队列 `userProfile.dlq`；`x-retry` 最多 3 次，超限进死信；ack/nack/publish 通过 `connection.add_callback_threadsafe` 回消费者线程。
- 新增 `GET /health` 与 `scripts/check_connectivity.py`。

## 验证

```powershell
curl http://localhost:5000/health
python scripts\check_connectivity.py

# 同一 uid 并发两次
python -c "import concurrent.futures,requests; uid=1104475649555097; u=f'http://localhost:5000/userProfile/{uid}'; f=lambda _: requests.get(u,timeout=600).status_code; print(list(concurrent.futures.ThreadPoolExecutor(2).map(f,[1,2])))"
```

- `/health` 五项全 ok（MySQL/Redis/RabbitMQ/ES/后端网关）。
- 并发两次均 200；`video.user_tag` 中该 uid 每个 `(uid, tag_name)` 只有一条。
- 发送一条 `{"uid": {"bad": 1}}` 的无效消息后，重试 3 次进入 `userProfile.dlq`，消息头保留 `x-retry=3` 与 `x-error`。

## 运维注意

- 上线新队列后，需解绑/删除旧的 `userProfile.queue1`（本次验证已解绑），否则消息会被两个队列重复消费。
- 健康检查只读，不会触发画像构建。
